# API Contracts - Portfolio Management System

This document defines the v1 REST contract for the portfolio backend.
If an endpoint, field, or status code changes, update this file before implementation.

## 1. API Scope and Conventions

- Base path: `/api/v1`
- Format: JSON (`Content-Type: application/json`)
- Auth: none required for v1 (single user assumption)
- Date format: `YYYY-MM-DD`
- Timestamp format: `YYYY-MM-DDTHH:mm:ss`
- IDs: numeric (`Long`)
- Asset type enum values: `STOCK`, `BOND`, `MUTUAL_FUND`

### Status Codes

| Code | Usage |
|---|---|
| 200 | Successful GET/PUT and refresh operations |
| 201 | Successful POST create |
| 204 | Successful DELETE |
| 400 | Validation error |
| 404 | Resource not found |
| 502 | External price service failed |
| 500 | Unexpected server error |

## 2. Resource Model

### 2.1 PortfolioItemRequest (create/update)

| Field | Type | Required | Rules |
|---|---|---|---|
| `type` | string enum | yes | one of `STOCK`, `BOND`, `MUTUAL_FUND` |
| `symbolOrName` | string | yes | not blank, max 100 |
| `quantity` | number | yes | must be > 0 |
| `purchasePrice` | number | yes | must be > 0 |
| `purchaseDate` | string (date) | yes | past or present |
| `currentPrice` | number | no | if provided, must be > 0 |

### 2.2 PortfolioItemResponse

Includes all request fields plus computed/managed fields:

| Field | Type | Notes |
|---|---|---|
| `id` | number | generated by server |
| `currentValue` | number | computed: `quantity * currentPrice` |
| `gainLoss` | number | computed: `currentValue - (quantity * purchasePrice)` |
| `gainLossPercent` | number | computed percentage |
| `createdAt` | string (timestamp) | server managed |
| `updatedAt` | string (timestamp) | server managed |

## 3. Endpoint Catalog

### 3.1 Portfolio Item CRUD

| Method | Path | Description |
|---|---|---|
| GET | `/portfolio-items` | list all items |
| GET | `/portfolio-items?type=STOCK` | filter items by type |
| GET | `/portfolio-items/{id}` | get one item |
| POST | `/portfolio-items` | create item |
| PUT | `/portfolio-items/{id}` | update item |
| DELETE | `/portfolio-items/{id}` | delete item |
| POST | `/portfolio-items/{id}/refresh-price` | refresh stock price from market data service |
| POST | `/portfolio-items/{id}/buy` | buy quantity for existing stock holding (market execution price is server-side) |
| POST | `/portfolio-items/{id}/sell` | sell quantity for existing stock holding (auto-removes holding when quantity reaches zero) |

### 3.2 Portfolio Summary

| Method | Path | Description |
|---|---|---|
| GET | `/portfolio/summary` | total value, cost, gain/loss, allocation |
| GET | `/portfolio/performance?range=1M\|3M\|6M\|1Y\|ALL` | time-series of `totalValue`/`totalCost` for the dashboard's performance chart (US-15) |

## 4. Example Payloads

### Create Item Request

```json
{
  "type": "STOCK",
  "symbolOrName": "AAPL",
  "quantity": 10,
  "purchasePrice": 150.25,
  "purchaseDate": "2025-01-15",
  "currentPrice": 195.4
}
```

### Item Response

```json
{
  "id": 12,
  "type": "STOCK",
  "symbolOrName": "AAPL",
  "quantity": 10,
  "purchasePrice": 150.25,
  "purchaseDate": "2025-01-15",
  "currentPrice": 195.4,
  "currentValue": 1954.0,
  "gainLoss": 451.5,
  "gainLossPercent": 30.05,
  "createdAt": "2025-01-15T09:00:00",
  "updatedAt": "2026-08-01T07:30:00"
}
```

### Buy/Sell Request

```json
{
  "quantity": 2.5
}
```

For buy/sell, backend sets execution price and execution timestamp server-side and records trade history.

### Summary Response

```json
{
  "totalValue": 45230.75,
  "totalCost": 41000.0,
  "totalGainLoss": 4230.75,
  "totalGainLossPercent": 10.32,
  "itemCount": 14,
  "allocationByType": [
    { "type": "STOCK", "value": 30250.0, "percent": 66.9, "count": 9 },
    { "type": "BOND", "value": 8000.0, "percent": 17.7, "count": 3 },
    { "type": "MUTUAL_FUND", "value": 6980.75, "percent": 15.4, "count": 2 }
  ]
}
```

### Performance Response

```json
{
  "range": "1M",
  "points": [
    { "date": "2026-07-07", "totalValue": 41850.00, "totalCost": 41000.00 },
    { "date": "2026-07-08", "totalValue": 41920.30, "totalCost": 41000.00 },
    { "date": "2026-08-06", "totalValue": 45230.75, "totalCost": 41000.00 }
  ]
}
```

`range` is normalized to one of `1M`, `3M`, `6M`, `1Y`, `ALL` (unknown/omitted values fall
back to `ALL`). If the requested range predates every holding's `purchaseDate`, the series
is clamped to start at the earliest purchase date rather than showing an empty lead-in.

**Approximation note:** each holding's per-day price between its `purchaseDate` (priced at
`purchasePrice`) and today (priced at `currentPrice`) is linearly interpolated — the backend
does not replay full historical daily closes per holding, to avoid extra third-party API
calls (Twelve Data / MFAPI) on every dashboard load per NFR-03/US-13's controlled refresh
strategy. The final point for "today" always uses the exact live `currentPrice`. See
`PortfolioPerformanceService` Javadoc for the full rationale and future upgrade path.

## 5. Error Contract

All non-2xx responses should use this shape:

```json
{
  "status": 400,
  "error": "VALIDATION_ERROR",
  "message": "quantity must be greater than 0",
  "timestamp": "2026-08-04T10:15:30",
  "fieldErrors": [
    { "field": "quantity", "message": "must be greater than 0" }
  ]
}
```

`fieldErrors` is only included for validation errors.

## 6. External Price Failure Behavior

- Normal CRUD should still work if market data is unavailable.
- `refresh-price` returns `502` and leaves last known price unchanged.
- UI should show a non-blocking warning and keep displaying stale data.
